Precedence: scope/schema invalid error; duplicate event ->NOOP; OPTOUT/BOUNCE ->STOP+cancel; existing STOPPED/HANDED_OFF ->NOOP+cancel, preserving incoming evidence elsewhere; confirmed INTEREST ->HANDOFF+cancel; UNKNOWN ->QUARANTINE; AUTOREPLY ->NOOP (no reset of followup plan implicitly); QUESTION/OBJECTION only allow known approved template whose fact_ids are subset of approved facts, otherwise QUARANTINE; FOLLOWUP_DUE only ACTIVE, under cap, after cooldown, approved template, else NOOP/QUARANTINE. No unconstrained body generation. Stated interest must be semantic evidence from later classifier; reducer cannot guarantee that itself.

## Зафиксированные решения R1
Контракт — внутренний server-owned semantic event, не публичный JSON API. body письма не может установить kind, approved_template_id, policy или sender_ref. Доверенный адаптер аутентифицирует провайдера, коррелирует thread и валидирует классификацию перед вызовом; в этой волне используются только явно synthetic fixtures. Модуль не доказывает качество classifier. Интеграция обязана записывать каждый новый message_id, включая HANDED_OFF/STOPPED; NOOP запрещает новое действие, не запись входящего.

Все schema_version точные; scope event = client_id/runtime_campaign_id/lead_id/mailbox_ref/thread_id равен state. policy.sender_ref обязан равняться state.mailbox_ref. revision,max_followups,cooldown_seconds,followups_sent — int>=0, bool не разрешён; policy/product/locale непустые. Все даты timezone-aware, now awareness обязательна; observed_at>now+300сек ошибка. approved_templates[id]={body:str nonempty,fact_ids:list[str]}; referenced facts должны входить в approved_fact_ids.

Все решения возвращают schema_version FIRST_DECISION_V1, action,reason,expected_state_revision,event_id,policy_version,template_id,fact_ids,next_status,cancel_followups. Неиспользуемые template_id=null/fact_ids=[]. expected_state_revision=state.revision. STOP→next_status STOPPED,cancel_followups=true; HANDOFF→HANDED_OFF,true; прочие сохраняют status. Дубликат→NOOP, cancel_followups=true только если state STOPPED/HANDED_OFF. UNKNOWN→QUARANTINE,cancel_followups=true (до разрешения неопределённости); отсутствие разрешённого template/fact→QUARANTINE,true. AUTOREPLY→NOOP,false для ACTIVE. OPTOUT/BOUNCE выше существующего HANDED_OFF, duplicate выше stop (повторно уже применённого события).

FOLLOWUP_DUE: нет last_outbound_at→NOOP,false; future last_outbound_at→ошибка; достигнут cap или now-last_outbound_at<cooldown→NOOP,false; ровно cooldown разрешает PROPOSE_FOLLOWUP с разрешённым template. QUESTION/OBJECTION→PROPOSE_REPLY с разрешённым template. Это предложение, не факт отправки; reducer не увеличивает followups_sent/revision и не обновляет историю — это делает последующая транзакция после выполнения/receipt. Отклонённая схема/несовпадение scope — FirstDecisionError, без действий.

Уточнение инженерной проверки: корректно структурированный template с fact_id вне approved_fact_ids даёт QUARANTINE (не ошибку общей schema); malformed структура policy даёт FirstDecisionError. Scope/schema validation предшествует business precedence.
