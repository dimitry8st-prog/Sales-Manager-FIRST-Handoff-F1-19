# Возврат работы

Один ZIP, один корневой каталог F1-19_RETURN_R1. Включить:
- changes/: только добавленные/изменённые пути из allowlist относительно source/;
- RETURN_REPORT.txt: task_id, техническая/передаточная ревизия, project_id, source identity, ОС/версии, реализация, команды, exit codes, критерии PASS/FAIL/NOT_RUN, ограничения и точные шаги подключения;
- evidence/: сырые stdout/stderr и CHECKS_SUMMARY.json до/после, результаты собственных сценариев;
- DIFF.patch: воспроизводимый unified diff только разрешённых source paths относительно неизменной базы; для нового файла использовать /dev/null как старый путь;
- SHA256SUMS.txt: реальные SHA256 каждого файла возврата кроме самого SHA256SUMS.txt, отсортированные относительные пути;
- INTEGRATION_NOTE.txt: точный producer→новый callable→consumer, зависимости, схема/миграции, восстановление и незакрытые интеграционные проверки.

Не включать всю baseline повторно, .env, credentials, настоящую переписку, caches или исходники другого исполнителя. Исторический неуспешный лог сохранять отдельно; новые результаты не выдавать за старые. Известные чужие ошибки не исправлять в этом задании. Пустой набор тестов/skip не является PASS. Сеть, production DB, Make, worker и реальные отправки не нужны для самостоятельной приёмки вашего компонента.

После возврата: отдельный code/tests review → независимая проверка → инженер внедрения сверяет текущую целевую identity → bounded интеграция с receipt/rollback → независимая проверка итоговой версии. Кандидатский PASS не закрывает автоматически продуктовый FG и не означает, что пакет отправлен разработчику или внедрён.
